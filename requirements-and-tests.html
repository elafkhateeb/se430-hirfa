Project overview

Hirfa is a Java and SQLite handmade-goods marketplace. Customers can discover products, manage a cart, place and track orders, and pay using supported methods. Artisans create accounts and manage their own products and stock.

Testing approach

Black-box cases cover valid and invalid input partitions and relevant numeric boundaries. White-box tests are organized by service in test/com/hirfa/; run them with the bundled JUnit ConsoleLauncher. Generate a JaCoCo report using the commands in the repository README. Coverage values should be taken from the report generated for the current source revision.

The report covers the model, repository, service, and web application packages.

R01 — Customer registration

A customer can register with a name, Jordanian mobile number, unique email address, and strong password.

Implementation: CustomerService.register   JUnit: CustomerServiceTest

BDD scenarios

Feature: Customer registration

Scenario: Register with valid details
  Given a visitor enters "Nour Ayada", "0771112223", "nour@example.com", and "NourPass2026"
  When the customer registration form is submitted
  Then a customer account is created
  And the new customer is signed in

Scenario: Reject an email address already in use
  Given an account already uses "amal@example.com"
  When a visitor registers with the same email address
  Then registration is rejected with a duplicate-email message

Black-box test design

Technique / partitionInputExpected result
Valid partitionName, valid Jordanian phone, unused email, strong passwordAccount is created
Duplicate emailEmail already belongs to an accountRegistration is rejected
Invalid phonePhone number does not match the Jordanian mobile formatRegistration is rejected

Execution

Build and run the website from the repository root using JDK 17 or later:

javac -cp lib/sqlite-jdbc.jar -d build $(find src -name '*.java')
java -cp "build:lib/sqlite-jdbc.jar:lib/slf4j-api.jar" com.hirfa.web.WebServer handmade.db 8080

Run the JUnit suite with the commands in README.md. Standalone Gherkin files are generated under features/R01.feature through R20.feature.
